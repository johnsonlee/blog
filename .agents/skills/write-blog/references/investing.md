# Investing 类文章

Investing 类文章仍然先讲清一个产业、公司或资产如何运转。文章是否在做 alpha 分析，应由问题选择、证据和 economics 落点体现，不靠反复出现“投资”“投资者”“机会”或“alpha”。

## 先把产业判断写完整

研究笔记里至少要能回答以下问题，但不要把它们机械写成正文目录：

1. 需求由什么具体行为、合同或预算形成，需求单位是什么
2. 供给需要复制什么能力，从投入到可交付输出要多久
3. 哪个约束会影响交付、价格或竞争格局，持续时间有多长
4. 客户能否复用、扩建、换设计或换供应商绕开它
5. 谁控制客户绕不开的环节，又凭什么把稀缺转成价值
6. 当前价格已经隐含了多少增长、份额、margin 与持续时间，什么事实会证伪判断

当前瓶颈不自动等于 alpha。约束要同时经得住持续性、控制力、替代路径、价值捕获和 price-in 检查，才值得继续落到公司。

## 从技术约束走到财务结果

不要从一个技术名词直接跳到“受益股”。中间至少要走通三段：

**Operational constraint → commercial event → financial result**

Commercial event 取决于生意本身，可能是 capacity reservation、design win、purchase order、shipment、installation、acceptance、usage、renewal 或其他合同 gate，不必强行写成“下一笔付款”。再判断它怎样进入 backlog、revenue recognition、ASP、gross margin、working capital、cash flow 或 capex。

反过来检查公司数据能否沿同一条链回到具体约束。公司级增长或毛利不能自动证明某个产品形成瓶颈；行业 shipment 也不能自动证明某家公司拿到对应份额。

## Price-in 必须算出来

Price-in 不是“估值很高”或“股价已经涨过”的同义词，而是当前价格对未来经营结果隐含了什么预期。结论不能只写“市场尚未计入”或“已经充分反映”，必须说清计入的是哪个变量、哪个时间区间，以及这个判断怎样从当前价格推出来。

先把产业 thesis 沿同一口径换成公司 earnings path：

**Industry demand → addressable deliveries → company share → revenue → margin → cash flow → valuation**

再做两组可以比较的假设：

- **Thesis expectations**：文章根据交付能力、竞争位置、价格与成本推导出的 revenue、margin、cash flow 和持续时间
- **Implied expectations**：在当前股价、fully diluted shares、net debt 与选定估值方法下，市场必须假设什么经营结果才能得到当前 enterprise value 或 equity value

一个价格不能同时唯一反推出 growth、share、margin 和 duration。先把非核心变量固定在 consensus、management guidance、历史区间或明确的基础假设上，再反求 thesis 最关键的一两个变量。每个固定值都要说明选择依据、合理区间，以及它是否与待反求变量重复表达同一假设；否则所谓 implied expectations 只是作者挑中的一组答案。

所有输入必须属于同一个 information set。股价、fully diluted shares、net debt、guidance 与 consensus 分别标注来源和 `as of` 日期，不把估值日之后才公开的数据倒灌进当时的 price-in 判断。Fiscal year、calendar year、币种、GAAP/non-GAAP 和 segment/company 口径也要先对齐。

估值方法随生意选择。稳定现金流可以使用 reverse DCF；周期性或尚未稳定盈利的公司可以从 normalized earnings、EV/Sales、EV/EBITDA、sum-of-the-parts 或情景概率反推，但必须解释为什么这个方法能对应当前 earnings path。历史 multiple、peer multiple 和 analyst consensus 可以作为参照，不能代替 implied-expectation calculation。

Price-in ledger 至少要让以下口径处在同一张表里，并展示足够的公式或逐年 bridge，让读者能够从 price 复算到 operating assumptions，再从 valuation 回到 equity value：

- 估值日期、股价、fully diluted share count、net debt、equity value 与 enterprise value 的 reconciliation
- 当前 consensus 或 management guidance 的 snapshot 日期、预测年份、样本范围或分散度，以及使用的利润口径
- thesis、consensus 和 current price implied 的 revenue、margin、cash flow 或关键 operating variable
- revenue 到 earnings/cash flow、terminal value 或 exit multiple、discounting 与 EV-to-equity 的计算路径
- terminal assumption、multiple、discount rate 和固定变量的区间来源，以及关键变量的联合 sensitivity
- 哪一个差异真正构成 upside/downside，哪一个差异只是估值方法造成的

结论应当能够还原成一句可复算的话：当前价格大致隐含了什么，而 thesis 比它多假设或少假设了什么。合理的 multiple、margin、duration 或 discount rate 组合一变化，结论就反转时，正确结论是 price-in 判断不稳健，不是挑一组支持 thesis 的参数。Price-in 可以只发生在某个时间段或某一段价值链上，不是二元状态。无法从公开数据可靠拆出隐含预期时，明确写成未验证，不用股价走势、新闻热度或“市场还没意识到”替代计算。

## 证据边界

- 区分公告、意向、合同、在建、已交付、已验收和投入使用；选择与主题相关的状态，不把它们混成“落地”。
- 区分存量、增量、run rate、目标、估算和合同上限，避免重复计算。
- 把公司披露、第三方估算和作者推论分别标清。
- 把公司整体、segment、product line 和单一项目的财务口径分开，不用宽口径数字替窄口径 thesis 背书。
- 不为了显得完整罗列所有供应商、股票或风险；只保留推动当前判断的证据。

## 语气

像拆一笔生意一样讲故事。合同、产能、交期、替代、定价和现金流自己会说明文章在算什么，不需要类别标签替它们发言。技术解释走到 economics 时也不要突然切换成研报腔；让同一条因果链继续往下走。
