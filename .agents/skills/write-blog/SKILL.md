# Blog Writer

把材料组织成一篇像 Johnson 本人写的文章，而不是套用口头禅或博客模板。

## 先读什么

1. 先确认当前工作目录是 `johnsonlee/blog` 仓库，并读 `AGENTS.md` 和相关 package scripts。仓库规则优先于本 Skill。
2. 每次写作都读 [references/style.md](references/style.md)。
3. Investing 类文章再读 [references/investing.md](references/investing.md)。
4. 创建或修改 post 文件、站内链接或英文版时，读 [references/publishing.md](references/publishing.md)。
5. 文章需要图表或架构图时，读 [references/visuals.md](references/visuals.md)。

## 工作方法

### 1. 先建立正确理解

先读用户提供的材料、同主题旧文和 3-5 篇同类别文章。研究作者如何进入问题、怎样连接章节、判断落在哪里，不统计口头禅，也不复制某篇文章的开篇形式。

研究型文章、系列文章和长篇重写在动笔前必须先对齐一份 editorial brief：

- 读者从什么疑问或冲突进入
- 引子使用哪个具体事实、场景、数字或判断
- 全文最终要表达的一句话观点
- 问题如何逐层推进，每一节给下一节留下什么
- 哪些数据和事实支撑哪些判断，哪些仍是推测
- 哪些关系必须用图解释，哪些旁支明确不写

如果用户已经把这些信息讲清楚，直接复述并校准；缺少会改变主线的信息时，先对齐，不要用完整草稿试探方向。

### 2. 先完成证据和结构

涉及外部事实时，先建立 claim-to-source ledger，再写正文。区分事实、估算、推论和观点；数字必须带时间、单位、口径和状态。优先使用一手来源，不能用一条来源支撑它没有说过的结论。

把大纲写成问题链、因果链、时间线或交付链。章节标题只是这条链上的路标，不是若干并列知识点。只读相邻章节的结尾和开头，也应该能看出为什么必须继续往下读。

### 3. 中文定稿优先

先写中文。每一段都要接住上一段，增加一个事实或推论，再把问题推向下一段。先解决主线、证据和术语，再处理句式；不要用过渡词掩盖结构断裂。

完成后按以下顺序验收：

1. **观点**：能否用一句话说清全文判断。
2. **连续性**：能否沿一条逻辑链复述全文，而不是只能列章节。
3. **作者视角**：判断是否始终来自同一个作者，有没有突然变成解说员、教师或公关稿。
4. **证据与术语**：事实是否支撑判断，状态、层级、单位和专业术语是否准确。
5. **语言**：删掉模板句、重复解释、元话语和不承担信息的段落。

任一上游问题失败，回到结构重写，不能只润色暴露问题的那一句。

### 4. 中文稳定后再扩展

只有中文主线通过验收后，才生成英文版和最终配图。英文版是同一篇文章的母语化表达，不是旧稿翻译或独立改写；图表必须服务已稳定的叙事。

用户反馈如果推翻了文章理解，重新检查全文、英文版、配图和 Sources。不要收到一条反馈就只改一个局部，也不要把单篇文章的事故追加成全局写作规则。

### 5. 验证后再发布

运行仓库现有的 agent guidance、post style、quotes 和 Hexo build 检查；逐项核对双语章节、图片、正文链接和 Sources。图表需要实际渲染，不能只检查 SVG 源码。

只有用户明确要求发布、push、开 PR 或 approve 后，才执行对应的外部操作。遵循当前仓库的 branch/PR 工作流，不默认直接写入 `master`。

## 完成标准

一篇文章只有同时满足以下条件才算完成：

- editorial brief 与最终文章仍是同一个故事
- 开篇直接进入问题，结尾完成开篇留下的张力
- 每个章节都由上一节推导出来
- 观点、事实、推论和不确定性边界清楚
- 中文像原生写作，英文像原生英文文章
- 双语正文、Sources 和文字型配图保持事实一致
- 所有仓库检查和视觉检查已经执行，未验证项明确披露
