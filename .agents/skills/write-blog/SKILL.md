# Blog Writer

把一个问题研究透，再组织成一篇像 Johnson 本人写的文章。风格不是套用口头禅；深度也不是堆字数、术语、Sources 或配图。

## 按任务读取

1. 先确认当前目录是 `johnsonlee/blog`，读 `AGENTS.md` 和相关 package scripts。仓库规则优先。
2. 每次写作都读 [references/style.md](references/style.md)。
3. 产业、技术、公司、Investing、系列文章或任何需要外部证据的 deep dive，读 [references/research.md](references/research.md)。
4. Investing 类文章再读 [references/investing.md](references/investing.md)。
5. 文章需要图表、架构图或地图时，读 [references/visuals.md](references/visuals.md)。
6. 创建或修改 post、站内链接、英文版或准备发布时，读 [references/publishing.md](references/publishing.md)。

## 工作方法

### 1. 找回这篇文章真正要解决的问题

先读用户提供的材料、同主题旧文和 3-5 篇同类别文章。研究作者怎样选择问题、推进判断和收束，不统计口头禅，也不复制某一篇的开篇。

续写系列时，从上一篇真正停下的位置继续。先确认读者此刻已经知道什么、自然会追问什么，以及这篇准备把哪个模糊对象拆到什么分辨率。不要先定一个大类标题，再往里面填资料。

### 2. 先研究，后写完整草稿

研究型文章先按 [references/research.md](references/research.md) 建立分析对象的边界、状态、流程、依赖、量化关系与证据。事实清单不是系统模型；知道组件名称，也不等于知道它们怎样共同完成交付。

研究过程中维护 claim-to-source ledger，但不要把“已经写出的 claim 都有来源”误当成研究完整。发现关键环节只能用“然后”“最后”“完成后”带过，说明中间仍有 magic jump，继续研究机制、依赖、责任或验收证据，不用顺滑的句子掩盖它。

### 3. 对齐 editorial brief

研究型文章、系列文章和长篇重写在动笔前对齐一份 brief：

- 读者从哪个具体疑问进入，最可能误解什么
- 引子用哪个事实、场景、数字或冲突打开这个疑问
- 分析对象从哪里开始、到哪里结束，哪些旁支不写
- 全文最终要推导出哪一句判断
- 问题怎样逐层推进，每一节解决什么，又留下什么
- 哪些关键 claim 由什么证据支撑，哪些仍是不确定的
- 哪些结构、流程、依赖或数量关系必须让读者直接看见
- 读完以后，读者对这个对象的 mental model 具体改变了什么

用户已经把这些信息讲清楚时，复述并校准；缺少会改变主线的信息时先对齐，不用完整草稿试探方向。

### 4. 先把中文主线写通

先写中文。章节由读者的问题推出来，不按资料来源或知识分类排列。每一节都从读者此刻的理解出发，用机制与证据解决一个问题，再让答案自然改变下一个问题。

按上游到下游的顺序验收：

1. **深度**：从起点到结论是否仍有未解释的跳跃；关键状态、依赖、数量和责任边界能否追踪。
2. **观点**：全文是否真的推导出一个判断，而不是整理了一批正确资料。
3. **连续性**：能否沿一条因果链、问题链、时间线或交付链复述；章节换序后是否会破坏论证。
4. **作者视角**：判断是否始终来自同一个作者，有没有突然变成新闻摘要、教师或公关稿。
5. **证据与术语**：事实是否支撑对应 claim，状态、层级、单位和专业术语是否准确。
6. **语言**：删掉模板句、重复解释、元话语和不承担信息的段落。

任一上游问题失败，回到研究模型或结构重写，不能只润色暴露问题的那一句。

### 5. 把反馈作用到上游

用户反馈如果改变了文章切入点、系统边界、问题链或判断，重新检查全文、英文版、配图和 Sources。不要局部打补丁后保留旧结构，也不要把单篇文章的一次事故追加成全局禁令。

### 6. 中文稳定后再扩展

中文主线通过验收后，再生成英文版和最终配图。英文版是同一篇文章的母语化表达，不是旧稿翻译或独立改写；图表必须服务已经稳定的叙事与证据。

### 7. 验证后再发布

运行仓库现有的 agent guidance、post style、quotes 和 Hexo build 检查；逐项核对双语章节、图片、正文链接和 Sources。图表需要实际渲染，不能只检查源码。

只有用户明确要求发布、push、开 PR 或 approve 后，才执行对应的外部操作。遵循当前仓库的 branch/PR 工作流，不默认直接写入 `master`。

## 完成标准

一篇文章只有同时满足以下条件才算完成：

- editorial brief、研究模型与最终文章仍是同一个问题
- 开篇直接进入问题，结尾完成开篇留下的张力
- 读者不只会复述组件，还能沿同一条链解释为什么会卡、条件变化后会发生什么，以及用什么证据判断当前状态
- 每个章节都由上一节推导出来，数据和图表各自承担明确问题
- 观点、事实、推论和不确定性边界清楚
- 中文像原生写作，英文像原生英文文章
- 双语正文、Sources 和文字型配图保持事实一致
- 所有仓库检查和视觉检查已经执行，未验证项明确披露
