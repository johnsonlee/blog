# johnsonlee.io 写作风格

## 作者视角

辨识度来自对问题的追究、具体经历和明确判断。文章像作者正在和读者看同一个对象，有事实，也有取舍；不靠口头禅、金句数量或中英混用模仿风格。

- 直接陈述观察与判断，不自称“笔者”或站在第三者角度分析作者。经历、责任和认识变化需要“我”时自然使用，不机械删除第一人称。
- 保留作者已有立场，不为了显得客观自动取中间值；立场需要的事实依据仍须核验。
- 真实经历中的动作、对话和处境可以承担情感与关系，不必都充当论证。不能为了“像真人”补造经历、数字或心理活动；虚构故事和假设案例保留明确标记。
- 写相关主题前读旧文；新判断与旧文不同时，交代新证据改变了哪个假设。复盘区分当时知道的、后来才知道的和现在的解释。
- 从 [samples.md](samples.md) 按需选取相近文体，学习段落的作用，不复制句式、场景或旧文事实。

## 连贯与节奏

推进方式按 `SKILL.md` 的文章目的选择。解释文让证据补足机制，叙事让事件、关系与时间产生变化；不要把所有段落都写成“推翻旧认识、提出新问题”。

- 因果、时间、决策或对照关系承担连贯性，不靠“镜头继续”“接下来看看”等转场词掩盖跳跃。
- 解释文检查后面的判断是否缺少前提；叙事检查场景为何出现在这里。章节可换序是检查线索，不是所有文体的失败判定。
- 每节应增加事实、理解或体验。若只是把同一结论换个比喻再说一遍，合并；留一句最有力的判断完成收束。
- 以完整意思划分段落，适合手机阅读但不写成连续 slide 文案。反问、短句与停顿只在确有作用时使用。
- “这”“两者”“前者”等指代必须立即可解。中英混用保持自然，稳定的技术术语保留英文。

## 开篇与收束

开篇给读者一个具体事实、现场、观察或处境，建立继续读的理由。解释文可以留下中心问题；回忆可以从一个动作或关系开始，不强造异常。避免时代背景、写作计划、目录预告和矫饰的场景。

`<!-- more -->` 前让引子完整成立，通常一至两个短段落，不只剩一句 slogan。正文接住引子，不突然改讲行业全景或无关概念。

结尾回应文章起点。解释文让读者看到问题怎样变清楚；叙事可以停在有分量的动作、细节或变化；探索可以指出还缺哪份证据。不要强加人生道理、课程总结、行动号召或空泛展望。

## 论证和解释

- 叙事可以 casual，名词、状态、单位、时空与事实口径必须专业。研究的证据规则见 [research.md](research.md)。
- 术语在读者需要它时出现，缩写在当前语境自然解释，不用名词堆积证明深度。
- 一个 case 可以贯穿推理；比较多个对象时说明可比性与各自作用。叙事中的人物和地点切换不等于偷换论证对象。
- 类比帮助读者进入问题，不能独自证明机制相同。写清它解释到哪里，跨过去的判断需要独立证据。
- 判断句落在推导完成的位置。预测的机制、规模和时点分别需要依据，不能用笃定语气补齐。

## 标题和章节

标题按 [titles.md](titles.md) 的作者偏好和语义检查设计；历史标题用于理解风格，不自动成为当前规则下的合格候选。标题要独立说明对象，不照抄目录或用统一系列前缀代替信息。

章节标题承载具体问题、判断、人物、事件或场景。不要用“背景”“分析”“启示”“总结”等空容器，也不要直接照抄研究框架的 Anatomy、Flow、Dependency、Economics。使用 `##` / `###`，不拿加粗充当标题；加粗只突出核心判断。

## 改稿检查

先查上游理解，再改句子：

- 是否先定终点再挑材料，或让一个很弱的反方代替真实分歧？
- 是否把类比当证明，把个人经历直接推广成行业或普遍规律？
- 是否删掉当时的不确定性，让作者在故事里始终提前知道答案？
- 是否为套认知路径抹掉人物、感受和观察，或为强调立场反复落槌？
- 是否用陌生术语、装饰性比喻或“不是 A，而是 B”制造没有证据的转折？
- 是否改变了原稿的事实、立场和适用条件，或在收尾补上无关道理？

这些是诊断问题，不是禁词表。已成立的表达原样保留；语言审查只修改有具体问题的段落。
