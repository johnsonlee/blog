# 系列与 Subsystem Deep Dive

系列框架是一张 curriculum map：它规定全貌由哪些 subsystem 构成，保证最终没有关键盲区。它不是文章模板。每个 subsystem 独成一篇，但仍然执行 `SKILL.md` 对所有 blog 的同一套认知契约和收敛路径。

系列文章额外处理跨篇边界和连续性：这一篇接住上一篇留下的哪个 gap，又把整体地图推进到了哪里。第 0 个问题、问题收敛和小白到专家的转换不是系列特例，因此不在这里另建一套规则。

## 系列连续性

- 从上一篇已经建立的认识继续，不复述整套方法论，也不站在第三者角度介绍旧文。
- 新读者即使没读上一篇，也应能从当前场景理解必要前提；不要依赖未解释的缩写和目录位置。
- 当前文章的结论可以打开下一篇，但不能用“下一篇将介绍”代替本篇收束。
- 目录回答的是全貌还缺哪些层，不要求正文逐项报告写作计划。

## 防止照本宣科

下面这些内容只有在它们是当前问题的必要答案时才进入正文：完整组件清单、标准交付流程、所有参与方、Gantt、商业模式、公司映射、price-in 和风险清单。它们不能因为在其他 subsystem 出现过，就成为系列的固定章节。

不同 subsystem 应当呈现不同的认知阻力。项目为什么慢，可能需要 critical path；容量为什么虚高，可能需要 reconciliation；网络为什么扩不动，可能需要 topology 与 failure domain。相同的是小白到专家的转换，不是文章的外形。
