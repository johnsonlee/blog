# 系列与 Subsystem Deep Dive

系列规划记录各篇共同追踪的主题及尚未解决的部分。产业系列可以用 subsystem map 检查覆盖范围，回忆或复盘系列可以按时间、人物或决策组织。规划不是文章模板；按 `SKILL.md` 为当前篇选择推进方式。

## 跨篇边界

- 读取相关已发布文章，确认当前篇承接什么、补充什么，是否有新证据修正旧判断。
- 新读者即使没读上一篇，也能从当前事实或场景理解必要前提，不依赖未解释的缩写和目录位置。
- 尊重用户确定的系列范围与篇章安排。尚未确定时，按每篇能独立完成的解释或叙事划分，不强制一个 subsystem 一篇。
- 当前篇须完成自身目的；结尾可以留下后续问题，不用“下一篇将介绍”替代收束。

## Deep Dive 的取舍

完整组件清单、标准交付流程、所有参与方、Gantt、商业模式、公司映射、price-in 和风险清单，只有在当前判断需要时才进入正文，不能因为其他 subsystem 写过就成为固定章节。

不同问题需要不同证据：项目周期可能需要 critical path，容量口径可能需要 reconciliation，网络扩展可能需要 topology 与 failure domain。沿各自的解释路径推进，不按同一张研究清单填空。
