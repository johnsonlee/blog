# Blogging

把作者的观察、经历和判断写成读者能够跟随的文章。保留工程师追究问题的习惯、亲历者的细节和明确立场，让证据决定判断能走多远。研究可以在后台发散，正文围绕文章目的收敛；研究框架不得直接变成文章目录。

## 先确认任务范围

读取仓库 `AGENTS.md`，区分策划、研究、新稿、局部修改、翻译和完整发布。沿用用户明确的主题、文体和交付范围；普通编辑不自动变成选题、全篇重写或发布任务。

- 新写文章通常先完成中文；纯翻译从用户指定的稳定原稿出发，不另起中文稿。
- 任何新增或修改的 published post 必须同时交付中文和英文版本，这是仓库 hard gate。局部修改也须检查配对，补齐缺失版本；已有另一版只修改受影响内容，不为形式一致重写整篇。
- 新建正式文章、草稿转正式文章及完整发布准备，交付双语正文和 5:2、3:4 两套封面；正文配图按需要选择。仅策划、研究、草稿或局部改稿不自动补全整套发布资产。
- 改动事实、标题或图示时，追踪既有双语正文、图、封面和导出文件的实际依赖并同步受影响部分。修改正文不等于必须重新生成所有资产。
- 只有用户明确要求 push、开 PR、merge 或发布时才执行对应外部操作。开 PR 不包含合并或部署授权。

## 按需读取

- 写作与改稿：读取 [style.md](references/style.md)。按主题和文体检索相关旧文；[samples.md](references/samples.md) 提供少量正例入口。
- 拟定、修改或审查标题：读取 [titles.md](references/titles.md)。历史案例仅在命中相同问题或追查规则依据时读取。
- 需要外部证据、技术解释或产业研究：读取 [research.md](references/research.md)。观点涉及公司价值捕获或估值时，再读 [investing.md](references/investing.md)。
- 系列或 subsystem deep dive：读取 [series.md](references/series.md)。
- 创建或修改 post、翻译、站内链接及发布准备：读取 [publishing.md](references/publishing.md)。
- 正文配图、封面、SVG/PNG 导出或修改已有视觉资产：读取 [visuals.md](references/visuals.md)。完整发布准备即使没有正文配图，也必须读取封面要求。

## 选择推进方式

先用简短内部笔记明确文章目的、读者已有认识、已有材料和不写什么。笔记用于作出取舍，不是每篇必须填满的表格；局部改稿保留原有结构，除非问题来自结构本身。

| 文章目的 | 主要推进方式 | 验收关注点 |
|---|---|---|
| 解释、技术或产业 deep dive | 从具体问题沿证据、机制与边界推进 | 读者能解释新案例，知道模型在哪些条件下成立 |
| 回忆、生活观察 | 经历、动作、关系和时间中的变化 | 具体细节承载感受，不强行提炼普遍规律 |
| 决策或项目复盘 | 当时信息、选择、代价、结果与修正 | 不把事后解释倒灌成当时已知，保留合理但失败的尝试 |
| 观点探索 | 候选解释及其分歧，逐步确认已知与未知 | 说明判断依据和仍未解决的部分，不为闭环制造答案 |

这些是选择依据，不是四套章节模板。可以混合使用，但每段应服务同一篇文章的目的。解释文适合连续因果链；叙事中的场景、停顿和情绪不必逐段推翻一个观点。

## 先检验候选判断

研究型任务在搜索前记录：

```text
中心问题与边界：在解释哪个对象的什么现象
候选判断：目前倾向什么，依据与未知是什么
竞争解释：懂行的人为何可能不同意；没有可信替代时不虚构反方
区分证据：什么观察会使候选判断保留、收窄或失效
```

用户已明确立场时，保留其关切和判断强度，检验事实依据与适用范围；证据与立场冲突时明确指出冲突，不编造支持材料，也不默默折成温和中间值。无法确认用户经历或意图且会改变文章主旨时，提出具体问题，继续不依赖答案的工作。

按 `research.md` 核验材料后再决定正文结论。保留、收窄、推翻候选判断或暂未定论都可以成立。对照相关旧文，交代什么新事实改变了旧判断；不能只从历史中挑选支持当前结论的段落。

## 收敛成正文

解释型文章从读者可感知的问题出发。第 0 个问题应暴露基本常识尚未解决的解释缺口；存在竞争解释时，再说明怎样区分它们。不能把“合同不等于交付”之类常识包装成发现。读者的直觉也可能成立，此时正文应说明机制或边界，不制造反转。

证据明确后，选择让读者理解判断所需的路径。复杂论证可用“当前认识 → 新证据 → 理解变化”检查跳步，不要求每段填表或留一个问号。类比、数字、术语和图只在它们增加解释力时进入正文；跨案例、时间或尺度的转换写明关系与可比性，不能悄悄更换论证对象。

叙事与复盘保留当时的犹豫、具体代价和错误的第一判断；不为了顺畅编造经历或删除关键的不确定性。各节可以通过因果、时间、决策或对照连贯，结尾的处理按 `style.md` 随文章目的选择。

## 审查与交付

先检查结构、事实和判断，再做语言审查。使用 `$humanizer` 检查受影响文本，修改有具体问题的段落；已经成立的表达可以原样保留。作者样本与 `style.md` 优先于通用措辞建议。若该 skill 不可用，按本 skill 的风格规则完成审查并说明实际采用的方式，不声称运行了它。

语言修改不得改变 claim、数字、日期、引用、链接、不确定性和作者立场。发现这些上游问题时回到研究或结构修正，再检查相关双语与资产，不让 prose QA 偷改结论。

按 `publishing.md` 完成适用的 `npm run check:bilingual` 和完整构建；视觉变更按 `visuals.md` 实际渲染。只修改 skill 文档时检查规则一致性和本地链接；显著修改流程时用真实任务做独立前向验证，不能用自行评分代替行为证据。

交付前确认：

- 文章实现了选定目的，保留作者视角与必要细节，没有靠重复判断或模板制造力度。
- 事实、推论、类比和预测可区分；研究结论经得住竞争解释，未解决之处明确。
- 与相关旧文的关系清楚；认识变化有依据，局部编辑没有意外改变主旨。
- 公司与估值判断遵守 `investing.md` 的证据链，走不通的部分明确停下。
- 已约定交付物及受影响的双语、Sources、图和封面一致，并通过对应验证。
