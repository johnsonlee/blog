# Blogging

把作者已经看见的系统，变成读者能够亲自走到的判断。johnsonlee.io 的深度不来自篇幅、术语、Sources、配图或固定分析框架，而来自一条连续的认知路径：读者最初觉得答案很简单，证据让这个答案失效，必要的系统结构随之出现，原来的问题因此获得更高分辨率。

**研究可以在后台发散，正文必须收敛。** 研究框架用于防止遗漏，不得直接变成文章目录。

## 按任务读取

1. 确认当前目录是 `johnsonlee/blog`，读取 `AGENTS.md` 和相关 scripts；仓库规则优先。
2. 每次写作都读取 [references/style.md](references/style.md)。
3. 系列文章和 subsystem deep dive 读取 [references/series.md](references/series.md)。
4. 产业、技术、公司或任何需要外部证据的文章读取 [references/research.md](references/research.md)。
5. Investing 类文章再读取 [references/investing.md](references/investing.md)。
6. 文章需要图表、架构图或地图时读取 [references/visuals.md](references/visuals.md)。
7. 创建或修改 post、站内链接、英文版或准备发布时读取 [references/publishing.md](references/publishing.md)。
8. 结构、事实和判断稳定后调用 `$humanizer`；作者样本与 [references/style.md](references/style.md) 的优先级高于通用 humanizer 规则。

## 先定义认知契约

无论是独立 blog 还是系列文章，在搜索资料或列目录前都先写一份内部 brief：

```text
分析对象：这篇只追踪什么对象；起点和终点是什么
小白模型：读者看见什么；最可能给出什么朴素答案
专家模型：行业专家会多看见哪些关系、边界和验证信号
第 0 个问题：不用术语也成立、能够暴露小白模型的具体问题
最终判断：全文必须推导出的判断，不是预先宣布的口号
最短路径：要让朴素答案失效，最少需要补上哪几层认识
不写什么：哪些正确内容会让对象或问题发生漂移
```

第 0 个问题不是“介绍一下 X”，也不是把研究清单改写成一串问号。它来自读者已经看见的具体矛盾，小白凭现有常识能够先给出一个答案，而真实系统会让这个答案失效。

续写时再写清上一篇已经改变了读者的哪一层认识，以及当前仍未闭合的 gap。用户给出的切入点、判断或边界已经明确时，直接采用；只有缺失信息会改变主问题或结论时才提问。

Subsystem、产业链地图和研究框架只决定这篇研究到哪里，不决定章节怎样排。不能因为系列目录规定了一个 subsystem，就从定义、组件、流程、项目计划、商业模式到 price-in 逐项填空。

## 后台研究，前台收敛

先按 [references/research.md](references/research.md) 建立足够完整的系统模型和 claim-to-source ledger。研究可以追踪多条路径，正文只选择能够闭合认知契约的最短路径。

为候选段落维护一张内部认知表：

```text
读者此刻相信什么 | 哪个事实使它不够用 | 必须补上的模型 | 理解改变后只剩哪个问题
```

每一步必须同时通过四项检查：

- 仍在回答第 0 个问题，没有换分析对象、状态、单位、时间或地域
- 解决的是上一段留下的必要 gap，不是作者想到的另一个相关问题
- 新术语、新数字和新图都改变读者的判断；删掉不影响推理的内容就不进入正文
- 答案会收窄可能性，并把同一个问题推进到更精确的一层，不会横向长出问题清单

每提出一个新问题，都检查：如果上一层没有回答，读者会不会自然问它？回答以后，候选解释是否变少？如果答案是否定的，它就是旁支，不是推进。

这不是把答案藏起来，也不是连续反问。作者知道终点，但让冲突和证据在正确的时刻迫使模型升级。

## 写出中文主线

先完成中文。开篇让读者看见一个具体异常、冲突、数字或现场，并留下第 0 个问题；下一段继续收紧它，不切换到行业全景、术语解释、供应商或股票。

正文从小白模型出发。先让朴素答案充分成立，再用现实矛盾暴露它解释不了的地方；只引入解决当前矛盾所需的结构、机制和证据。每一节的结论成为下一节的输入。专业术语在读者已经需要它时出现，配图在文字无法完成那次认知转换时出现。

写完后沿上游到下游验收：

1. **对象**：开篇、中段、结论是否始终追踪同一个对象和状态变化。
2. **认知**：每一节具体推翻或补全了读者哪一个旧理解。
3. **因果**：章节换序或删除后，后面的判断是否会失去前提。
4. **深度**：读者能否用新模型解释另一个案例，而不是只记住组件名称。
5. **判断**：结论是否由模型和证据推出来，而不是换句话重复新闻。
6. **语言**：作者视角是否稳定，是否出现教材、研报、新闻摘要或写作说明的口吻。

任一上游问题失败，回到认知契约、研究模型或路径重写；不要只润色暴露问题的句子。

## Economics、配图与扩展

Investing 类文章按 [references/investing.md](references/investing.md) 检查 operational constraint 能否沿真实 commercial event 进入具体公司的财务结果，再判断市场价格隐含了什么。不能为了完成“alpha”或“price-in”章节临时找一家行业相关公司。

主线稳定后再按 [references/visuals.md](references/visuals.md) 设计配图。没有固定图数，也没有标准 anatomy、Gantt、timeline 套餐。每张图都必须对应一次明确的模型升级。

用户反馈改变了切入点、边界或判断时，重做认知路径，并同步检查全文、英文版、配图和 Sources。中文稳定后再生成英文版；英文版表达同一条推理链，不翻译旧稿，也不另写一篇。

## Humanizer 与验证

中英文分别执行 `$humanizer` 的完整 rewrite process。它只负责 prose QA，不得增加、删除或改变 claim、数字、日期、引用、链接、不确定性和作者立场，也不能把 casual 叙事洗成百科文本。

按 [references/publishing.md](references/publishing.md) 验证 front matter、站内链接、双语对应、Sources 和构建；视觉交付按 [references/visuals.md](references/visuals.md) 实际渲染检查。只有用户明确要求 push、开 PR、merge 或发布时才执行外部操作。

## 完成标准

- 读者能说明最初的朴素答案为什么失败，以及哪个系统关系改变了答案
- 读者能把新模型用于另一个项目、新闻或公司，并知道下一步该查什么证据
- 全文只推进一个中心问题；没有从 case 跳到行业、从项目跳到公司或从机制跳到股票
- 章节、数字、术语和配图都承担不可替代的认知步骤
- Investing 结论走通约束、商业事件、财务结果和 price-in；走不通的部分明确停下
- 中文、英文、Sources、SVG/PNG 和封面事实一致，并通过仓库与视觉检查
